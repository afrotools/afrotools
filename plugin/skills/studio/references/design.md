# Phase: design

Goal: the user has seen and agreed how the app will look on their phone, before it is built.

1. **One question first**, in plain words: a look they like (an app they use, their shop's colours,
   a logo). If they have none, choose from what the business is.
2. **Write the direction** in `docs/design.md`, short: colours, one typeface (the system font, or one
   web font at most), sizes, the main components, and the rules below. Base it on the app's people and
   place, not on a generic template.
3. **Make one preview** of the main screen as a single static page, `docs/preview.html`, with real
   content in the user's language (real-looking names, prices in the local currency, dates). Tell the
   user how to open it (double-click the file, or on their phone if they can).
4. **Rules that keep it from looking generated by AI**, and usable where the app will be used:
   - no purple-blue gradients, no glowing cards, no emoji as icons, no cards inside cards, no stock
     "hero" banner: the screen starts with what the user came to do;
   - one accent colour used for actions only; text contrast at least 4.5:1;
   - phone first: one column, tap targets at least 44 px, the main action reachable with the thumb,
     forms with the right keyboard (`inputmode="numeric"` for amounts and phone numbers);
   - weak connection: no heavy images or video, at most one web font, pages that say clearly when
     something is loading or failed, and that keep what was typed;
   - states designed, not left to chance: empty lists, errors, payment pending, payment failed.
5. **Impeccable**: if the `impeccable` skill is available, ask once whether to use it on the preview,
   saying what it does for them (a design review by a specialist tool) and that it uses some tokens.
   Only after a yes, run `/impeccable critique docs/preview.html` and fix what it finds. Without a yes,
   or without Impeccable, review the preview yourself against the rules above. In both cases,
   `npx impeccable detect docs/preview.html` costs no tokens when Impeccable is installed: run it, it
   exits with code 2 when it finds problems.
6. **Agree**, then record the direction's path in `.afrotools/studio.md`, set `phase: build`, and say
   in one sentence what the next phase does.
